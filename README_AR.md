<a id="why-this-system"></a>
## 💡 لماذا هذا النظام؟ (The Core Thesis)

الإنترنت يغرق حالياً في **AI Article Generators** رخيصة؛ تطلب منها مقالاً فتنتج:
- مقدمات محفوظة: *"في عالمنا الرقمي المتسارع اليوم..."* أو *"سواء كنت مبتدئاً أو خبيراً محنكاً..."*.
- إعادة تدوير سطحية لأول 3 نتائج في Google.
- إحصائيات وهمية وهلاوس بدون مصادر حقيقية.
- انعدام تام للأرقام الواقعية، المعادلات الحسابية، وتحديات التنفيذ الميدانية.

**النتيجة؟ مقال مكرر لا يقرأه أحد ويفقد موقعه تصدر نتائج البحث.**

### `i-have-blog` ليس مجرد أداة ذكاء اصطناعي، بل **نظام تحرير مؤسسي (AI Editorial Operating System)**.

مستوحى من الانضباط الهندسي لمشروع [`ayghri/i-have-adhd`](https://github.com/ayghri/i-have-adhd) (الذي أثبت أن قوة الـ LLM ليست في الـ Prompt العشوائي، بل في وجود مصدر موحد للحقيقة `SKILL.md`، ومواءمة مع بيئات عمل متعددة، واختبارات قياس عمياء تقارن المخرجات بالـ Baseline).

<a id="architecture"></a>
## 🏛️ الهندسة المعمارية: مسار الإنتاج ذو الـ 10 مراحل

بدلاً من فوضى تعدد الوكلاء (13 وكيلاً يتحدثون ويهدرون الـ Tokens ويفقدون السياق)، يعتمد النظام على **منسق مركزي موحد (Single Orchestrator)** يدير مراحل مستقلة تنتج ملفات JSON قابلة للمراجعة والتصحيح:

```
الموجز (Brief) 
      ↓
[1] تحليل نية البحث وفجوات المنافسين (02_research.json)
      ↓
[2] استراتيجية الكيانات وزاوية التميز (03_strategy.json)
      ↓
[3] الهيكل المعماري للمقال H2/H3 (04_outline.json)
      ↓
[4] سجل الأدلة وتتبع الادعاءات (05_evidence.json)
      ↓
[5] مسودة مقسمة قسماً بقسم (06_draft.md)
      ↓
[6] فحص الحقائق وسياسة الحداثة (07_fact_check.json)
      ↓
[7] الجراحة التحريرية واستئصال الحشو (08_editorial_audit.json)
      ↓
[8] محرك الروابط الداخلية الدلالية (09_internal_links.json)
      ↓
[9] حزمة النشر النهائية الكاملة (10_final_package.md & json)
```

<a id="claim-registry"></a>
## 🏷️ سجل الادعاءات وتصنيف الحقائق (Claim Registry)

لا يسمح النظام بتمرير أي ادعاء مجهول المصدر؛ يتم ترقيم كل معلومة داخلياً بـ `[claim:C-xxx]` وتصنيفها:
1. **FACT**: حقائق تقنية ومستندات رسمية (مثل بنية الأنظمة والـ APIs).
2. **STATISTIC**: أرقام وإحصائيات لا يتعدى عمر توثيقها 12 شهراً.
3. **TIME-SENSITIVE**: أسعار وسياسات برمجية لا يتعدى عمر توثيقها 4 أشهر.
4. **EXPERT_INTERPRETATION**: تحليل واستنتاج ناتج عن تجارب عملية.
5. **OPINION**: وجهة نظر شخصية للناشر معلنة صراحة كـ Opinion.
6. **CALCULATION**: معادلات وحسابات رياضية معلنة المتغيرات والنتائج.

<a id="differentiation"></a>
## 🎯 معادلة درجة التميز (Differentiation Score)

لكي نضمن أن المقال لا يُعيد كتابة ما قاله المنافسون في Google، تحسب الخوارزمية درجة التميز من 0 إلى 100:

$$\text{Score} = \text{Base}(50) + \Delta_{\text{المعادلات}} + \Delta_{\text{جداول البيانات}} + \Delta_{\text{الأرقام الحقيقية}} + \Delta_{\text{نماذج الناشر الحصرية}}$$

> [!IMPORTANT]
> **بوابة الجودة (Quality Gate)**: يتم رفض وإيقاف نشر أي مقال تقل درجة تميزه عن **70 / 100**.

<a id="content-decay"></a>
## 🔄 محرك تجديد المحتوى وتراجع الزيارات (Content Decay Engine)

المدونات الناجحة لا تعتمد فقط على كتابة محتوى جديد، بل على **تحديث المحتوى القديم الذي بدأ يخسر زياراته**.
يحسب النظام نسبة تقادم المقال ويحدد الإجراء فوراً:
- **أقل من 25**: مقال متصدر ومستقر (`KEEP`).
- **25 إلى 50**: مقال مستقر يحتاج مراقبة وإضافة رابط داخلي أو رابطين (`KEEP_MONITOR`).
- **50 إلى 75**: تحديث جراحي للأسعار والإحصائيات القديمة (`UPDATE`).
- **أعلى من 75**: إعادة كتابة وهيكلة شاملة لأن نية البحث في السوق تغيرت بالكامل (`EXPAND_AND_REWRITE`).

<a id="installation"></a>
## ⚡ التثبيت والتشغيل عبر سطر الأوامر (CLI)

النظام يعمل كـ CLI كامل ومستقل مكتوب بلغة Python:

```bash
# استنساخ المستودع
git clone https://github.com/khaledmokhtar/i-have-blog.git
cd i-have-blog

# تثبيت الأداة
pip install -e .

# تشغيل دورة التحرير الكاملة لمقال جديد
blog-engine run --topic "Facebook Ads ROAS vs MER" --keyword "roas vs mer"

# فحص مقال قديم واحتساب نسبة تراجعه وخطة تحديثه
blog-engine refresh --target "https://myblog.com/guide" --age 16 --traffic-loss 30.0

# تشغيل اختبارات التقييم الـ 10 المعيارية
blog-engine evals

# تشغيل محاكاة التحكيم الأعمى
blog-engine judge
```
